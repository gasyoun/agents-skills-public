
Not every durable file earns a full pass. Three speeds:

1. **Skip entirely** — trivial artifacts: typo fixes, one-line README tweaks, comment-only
   edits, reformatting with zero content change. Record ONE line in the session log
   ("trivial — no sweep") instead of walking surfaces.
2. **Core-8 fast path** (default for small-to-medium docs: a single manual section, a small
   report, a one-off note promoted to durable): README · CLAUDE.md · cold-start doc ·
   changelog → `/cut-release` · `.ai_state.md` · metadoc · GTD (human actions only) ·
   SKILLS_INDEX (skills only). Walk these eight; for everything else in Phases 1–2 record
   the negative verdict in bulk ("core-8 pass — rest n/a: minor doc").
3. **Full sweep** (all of Phases 1–2) when ANY of: the artifact introduces a reusable
   capability/dataset/interface/skill; touches money/access/security; creates or changes
   cross-repo edges; closes a handoff; OR the user has already asked «а в X?» twice about
   this workstream. When unsure between 2 and 3 — run 3; the script makes 3 cheap.
