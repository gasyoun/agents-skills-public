# /md-hygiene

_Created: 03-07-2026 · Last updated: 05-09-2026_

## Default path (seconds — run this first)

From the Uprava clone root (canonical script:
[`tools/md_hygiene.py`](https://github.com/gasyoun/Uprava/blob/main/tools/md_hygiene.py)):

```sh
python tools/md_hygiene.py <target>
python tools/md_hygiene.py <target> --apply
python tools/md_hygiene.py --selftest
```

Those three flags are the whole CLI (`target`, `--apply`, `--selftest`). `--selftest` runs the fixture suite — including the H3923 DEAD-REF fixtures, which resolve against the **real** GitHub root — and prints `SELFTEST PASS|FAIL`; run it before trusting a surprising sweep, since a false DEAD-REF usually means the clone layout, not the doc, is wrong.

(The script-first default path is the H2795 shape — Sonnet 5, the Uprava
`zj-md-hygiene-sweep` handoff.)

LLM / judgment residue only after the script report exists (or the script exits non-zero with a real defect).

Argument: **exactly one** target — a path to a directory or a single `.md` file (`target` is `nargs="?"`, default `.`), so a list of files (`md_hygiene.py a.md b.md`) is an argparse error; sweep the directory instead. A bare **repo name** works only when your cwd is the GitHub root — the script does `Path(target).resolve()` against cwd and exits **2** with `no such path` otherwise, so from the Uprava clone root above you must write `../<Repo>`, not `<Repo>`. (`GITHUB_ROOT` inside the script resolves *dead references*, not this argument.)

Enforces the doc rules that have needed repeated manual correction. Applies to **authored** Markdown (docs, plans, roadmaps, handoffs, `.ai_state.md`, README-style references) — not throwaway scratch, and generated/machine-output MD only gets the no-HTML check plus an `_Auto-generated by X._` note instead of the byline.

The script reports dated-header / byline / full-URL / no-HTML defects and classifies
authored vs. generated vs. third-party as a hint. `--apply` only performs the
one safe mechanical fix (relative → full blob URL when the target path
resolves) — it never invents an org, never stamps today as Created, never
autocorrects DD-MM-YYYY to ISO. Everything the script flags but does not fix —
ambiguous authored/generated calls, messy `git log --diff-filter=A` history,
actionable-link specificity (item 5 of Phase 2 below) — stays LLM judgment per the
phases that follow.

## Phase 1 — Inventory

Glob `**/*.md` under the target (scope to the repo, not the GitHub root). Classify each file: authored / generated / third-party (vendored, upstream-owned — skip third-party entirely). Determine ORG and default branch once per repo via `git remote -v` — SanskritLexicography and VisualDCS are `gasyoun` personal repos, not `sanskrit-lexicon`; a blob URL with the wrong org is worse than no link.

## Phase 2 — Per-file checks and fixes

For each authored file, fix all of:

1. **Dated header** directly under the title: `_Created: DD-MM-YYYY · Last updated: DD-MM-YYYY_`.
   - Real creation date: `git log --follow --diff-filter=A --format=%ad --date=short -- <path>` (last line), converted ISO → DD-MM-YYYY. Never guess; never stamp today as "Created" on an old file.
   - Bump "Last updated" only if this sweep actually changes the file.
   - DD-MM-YYYY is deliberate — the one place ISO is NOT used; don't autocorrect it.
2. **Byline** `_Dr. Mārcis Gasūns_` as the very last line (generated MD: `_Auto-generated by X._` instead).
3. **No HTML in .md** — replace `<p align>`, `<sub>`, `<br>`, `<details>` etc. with plain-Markdown equivalents (the italic header/byline form above; for an indented/muted line — e.g. the FINDINGS registries' `> Source:` paragraphs — the equivalent is a blockquote `> `, keep those as blockquotes). Exception: keep HTML that has no Markdown equivalent AND is load-bearing (rare; note it in the report). A `<div align>`/`<sub>` styling experiment was tried and rejected 02-07-2026 — never reintroduce it.
4. **Links** — every filename, path, and URL rendered as a clickable Markdown link:
   - Committed repo MD (handoffs especially): **full** `https://github.com/ORG/REPO/blob/<branch>/path` URLs, `/tree/` for directories, `/issues/N` for issues/PRs. Relative links are a defect — upgrade them.
   - Conflict rule: where history shows full URLs were downgraded to relative (merge resolution, linter), re-upgrade — full always wins.
   - Bare backticks stay only on code identifiers (functions, flags), never on linkable files.
   - Verify each generated URL's path actually exists in the repo at that branch before writing it.
5. **Dead references — does the target actually exist?** (folded in from
   [H3923](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H3923-Opus_claude-config_skills-usage-ranked-review-tierB_02.09.26.md),
   MG ruling «fold», 02-09-2026.) Check 4 asks whether a link is well *formed*; this asks
   whether it points at anything. They fail independently, and the second failure is
   invisible on the page — a perfectly formatted blob URL 404s only when someone clicks it.
   Script-enforced (`DEAD-REF` / `DEAD-REF-ARCHIVED`), so this is a report you read, not a
   pass you perform:
   - **Full blob URLs** into a repo with a local clone are resolved against
     **`origin/<branch>`**, not the working tree — a stale clone otherwise invents dead
     references for files that shipped days ago (measured: a 78-commit-behind clone reported
     four live files as missing). No local clone ⇒ **silent**, never a guessed defect.
   - **`handoffs/H###-*.md` that moved to `handoffs/archive/`** get their own verdict,
     `DEAD-REF-ARCHIVED`, because that is the one dead-link shape with a mechanical repair —
     13 of the 21 H3923 found were this. **Not every dead handoff link is repaired by
     inserting `archive/`:** 6 of them named a filename that never existed, two with the wrong
     tier *and* the wrong repo (`H800-Opus_SanskritGrammar_quantifier-…` is really
     `H800-Fable_SanskritGrammar_gradation-…`). Resolve those against the real archive
     listing, never by pattern.
   - **Bare repo-relative script paths** under `tools/`, `scripts/` and `hooks/` are resolved
     against every clone under the GitHub root — these are written without a repo prefix, so
     "exists in no repo at all" is the only honest bar. A **prose placeholder** telling the
     reader to *create* a file (`/computed-table`: "write a `tools/name_check.py` generator")
     is indistinguishable from a reference and will be flagged; write placeholders with an
     angle-bracket stem so they never look like a real path.
   - Paths inside fenced blocks are **examples, not references**, and are skipped; inline
     backticks are still checked, because that is how a real reference is normally written.
     A directory link matches by prefix (`ls-tree -r` lists blobs only), and a path present
     on disk but gitignored — a build/output dir — is not dead.
6. **Actionable-link specificity** — for action-list rows (GTD tables in `GTD_NEXT_ACTIONS.md`, `DECISIONS_NEEDED.md`, roadmap/`.ai_state.md` "Next Steps" queues, Credentials & Accounts rows): the link must point at the actual place the action is performed (the PR, the exact draft text with a line anchor, the repo settings page, the external service's real page) — not merely a doc that mentions the topic in passing. A row with no such link is not a defect to silently drop; flag it in the report as "no actionable link exists yet" so it doesn't read as done when it isn't. This is stricter than the general link-clickability check in item 4 — a row can have a valid clickable link and still fail this check if that link isn't the actionable one.

## Phase 2.6 — Structural table integrity, and the generator behind it (U44, 19-08-2026)

Checks 1–5 are about the doc *contract*. This one is about whether the Markdown
**parses as the author meant** — a different failure, and a quieter one: a broken
row does not look broken, it looks *absent*. A swallowed `GTD_NEXT_ACTIONS.md`
row silently drops a human action; a truncated rollup section reads as "nothing
there" rather than "generator gave up". Eleven sessions re-derived this between
12-08 and 19-08 (H2862 · H2995 · H2997 · H3005 · H3008 · H3009 · H3012 · H3013 ·
H3033 · H3037 · H3038) before it was written down.

**The five shapes, in the order they actually occur:**

1. **Escape-eaten pipes** — a hand-rolled parser splits the row on every `|`,
   including the `\|` that Markdown *requires* inside a cell. The cell truncates
   at its first escaped pipe. Hits richest cells hardest (code samples, shell
   pipes, alternations, long status notes). See
   [FINDINGS §496](https://github.com/gasyoun/Uprava/blob/main/FINDINGS.md).
2. **Unterminated rows** — a row missing its closing `|`, so the next line is
   absorbed into the last cell and one row vanishes from the rendered table.
3. **Wrapped bullets read as rows** — a bullet that soft-wrapped across lines,
   where the continuation begins with something the harvester scores as a new
   record.
4. **Orphan bullet blocks inside a table** — a bullet list pasted between rows;
   the table ends early and everything after it renders as prose.
5. **Truncated sections** — a regen that writes N of M sections and exits 0.
   The tell is a section that ends mid-sentence with no closing byline.

**The fix has two halves, and shipping only the first is the defect.** Repair the
data *and* the generator that emitted it — otherwise the next regen re-breaks the
same rows the same day, which is exactly what happened across H3005 / H3033 /
H3037. So:

- **Locate the writer before editing the file.** `grep` the repo's `tools/` for
  the output filename; a file with a `[generated-block: …]` marker or an
  `_Auto-generated by X._` byline is telling you the fix belongs upstream. If the
  writer is a hand-rolled `split("|")`, that is the bug — route it through the
  consumer's own parser (in Uprava, [`fruit_scan.ROW_RE`](https://github.com/gasyoun/Uprava/blob/main/tools/fruit_scan.py)),
  never a fresh one.
- **Match the consumer, not your intent.** The system acts on how the *reader*
  parses the row, so a trailing `\|` that the consumer treats as a closing
  delimiter must be fixed the consumer's way.
- **Never hand-edit a generated block** to make a lint pass. Fix the generator and
  re-run it; a hand-patched generated file drifts back on the next run and the
  drift check then fires on *you*.
- **Re-run the repo's own gate afterwards**, not just your eyes — in Uprava that
  is `python tools/gtd_active_state.py --check` and `python tools/regen_derived.py`.

**Report both halves separately** — "12 rows repaired" without "and the generator
that ate them" is a status line that will be false within a day.

## Phase 3 — Report + commit

- Emit a table: file · fixes applied (header/byline/HTML/links counts) · skipped-and-why.
- Commit with `docs: md-hygiene sweep` on the current branch. **Exception:** never commit in `csl-orig`; in repos not owned by us (org repos where doc style is upstream's call), report the defects instead of sweeping — flag, don't fix.
