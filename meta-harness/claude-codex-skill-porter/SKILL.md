## The default path is NOT this skill — it is edit-canonical-then-generate

For any twin that is a generated stub, a skill change is:

1. Edit the canonical `~/.claude/commands/<name>.md` — the ONLY place content changes.
2. Generate:
   ```sh
   python ~/.claude/scripts/generate_playbook_twins.py <name>          # --dry-run to preview; writes codex + grok twins
   ```
3. Audit to zero:
   ```sh
   python ~/.claude/scripts/audit_codex_twins.py --skill <name>
   python ~/.claude/scripts/audit_grok_twins.py --skill <name>
   ```
4. Commit BOTH config repos, path-scoped (`git commit <paths> -m …` — never
   `git add -A`; sibling sessions keep staged WIP in these repos), then push each
   (`fetch && rebase && push` retry until green).

Never hand-edit `~/.codex/skills/<generated>/SKILL.md`. If its summary looks
wrong, fix the canonical and regenerate.

## Phase 0 — run the mechanical audit first

```sh
python ~/.claude/scripts/audit_codex_twins.py          # add --verbose to list standalone skills
```

It walks every `~/.codex/skills/*/SKILL.md` and reports `NO_POINTER` · `DEAD_TARGET` ·
`WRONG_TARGET` · `SUSPECT_DIRECTION` · `NO_FRONTMATTER` / `NO_FM_NAME` / `NAME_MISMATCH` ·
`NO_YAML`, exiting **1** on any finding. It already knows the sanctioned variants
(thin-pointer stubs, line-wrapped pointers, alias shims, vendored standalones) —
**a finding is real**; do not re-derive them.

## What still needs THIS skill (the exceptions)

1. **Codex-native richer bundles** — deploy/CI skills especially (`render-deploy`
   2500+ words + 10 reference dirs, `netlify-deploy`, `vercel-deploy`, `gh-fix-ci`),
   and vendored bundles like `cloudflare-deploy`. There the **Codex side is
   canonical**: the generator REFUSES to overwrite them on two independent tests —
   `SUSPECT_DIRECTION` (twin > 2.0× the Claude word count) and `LINE_LOSS`
   (regeneration would drop > 40 lines; the floor is
   [H3769](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H3769-Opus_claude-config_lift-richer-twins-into-canonical_31.08.26.md)
   (Opus 5) — Lift the 4 richer Codex/Grok twins into their Claude commands, then regenerate) — exit 2 for a named skill.
   The fix when their Claude counterpart must improve is to **lift the rich content
   into the canonical command first**, then generate — never blindly repoint;
   `--allow-line-loss` is the deliberate-collapse escape ONLY after the lift.
2. **Standalone vendored skills** (28 with no Claude command, 02-09-2026) — port one by writing
   the Claude command FROM the bundle's substance, not a thin pointer at a richer doc.
3. **Generator refusals / auditor failures on a named skill** — diagnose which side
   drifted; if the twin got richer by hand, treat as case 1.
4. **Broken pointers inside hand-maintained twins** — a canonical-runbook pointer at
   a renamed/deleted target (the `pwg-slice`→`pwg-drain` class): repoint at the live
   runbook, or migrate the twin into the generator regime.

When adding a new sanctioned pointer form to the auditors, teach the script in the
same pass — otherwise the next run reports it as `NO_POINTER` and someone "fixes" a
correct file.

## Porting rules (unchanged by the regime shift)

- Frontmatter stays agent-neutral and trigger-rich; prefer "asks an agent" over naming a single host.
- **Description adaptation for Codex** (its validator is stricter than Claude's):
  no angle brackets, ≤1024 UTF-8 **bytes** (IAST/Cyrillic are 2–3 bytes each — measure
  `len(desc.encode('utf-8'))`), strict YAML (single-quote scalars containing `:`/`'`,
  double internal `'`), never slurp a trailing frontmatter key into the value — stop
  extraction at the next `^key:` line. Much apparent description drift is *intentional
  adaptation*, not staleness.
- Convert host-specific instructions to portable alternatives (shell, `gh`, local
  files, Markdown handoff) — never a Codex-only UI directive as the sole execution path.
- Resources stay minimal and one level deep; when porting a Codex-native skill to
  Claude, inline its `references/*.md` detail into the flat Claude command.

## Exit gate

```sh
python ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py <skill-folder>
python ~/.claude/scripts/audit_codex_twins.py     # must exit 0 (exit 1 = findings)
```

Then commit both repos (path-scoped staging; `~/.codex/.gitignore` is deny-all so a
genuinely new file needs an allowlist entry or it silently never reaches the backup;
claude-config ignores `/scripts/*` with per-file un-ignores). A `0 findings` run is
only trustworthy if the audit found the twins at all — the header must read a plausible
count, not `0 skills`. `Path.home()` resolves elsewhere in some profiles, so verify the
helper actually saw the trees.

## Stop conditions

Stop and report when a skill depends on a host-only tool with no practical equivalent
on the other host, a referenced resource is missing, or reconciling would change
behavior beyond portability cleanup. Also stop on a `SUSPECT_DIRECTION` finding you
cannot settle from substance alone — flipping canonical direction changes which doc
future sessions treat as authoritative; state word/reference counts and let a human decide.
