# gdocs — Google Drive → Markdown-база знаний

Забирает **Google Docs / Sheets / Slides** в базу знаний через MCP-коннектор
**claude.ai Google Drive**. Скачивание, конвертация и сохранение — силами Клода,
без скриптов, API-ключей и настройки OAuth (авторизацией управляет claude.ai).

> ## ⚠️ Два жёстких правила
>
> **1. Документ сохраняется ЦЕЛИКОМ и дословно.**
> Не «ключевые мысли», не пересказ, не «причёсанная» версия. Сохраняем весь
> текст: все абзацы, врезки и цитаты, таблицы, списки, примеры, подписи, сноски.
> Чистка — ТОЛЬКО формат (снять экранирование, починить кривые таблицы); ни одна
> смысловая единица не выкидывается. Если сомневаешься — оставляй.
>
> **2. Если документ уже есть в базе — СПРОСИТЬ, не перезаписывать молча.**
> Варианты: сохранить поверх (новая версия) или сделать копию. См. шаг 5.

## Триггеры

- Ссылка на `docs.google.com/...` в запросе
- «забери гугл-док», «сохрани этот документ в базу», «перенеси таблицу/презентацию»
- `/gdocs <url>`

## Предусловие: подключённый коннектор

Нужен подключённый коннектор **«claude.ai Google Drive»**. Если инструменты Google
Drive недоступны (`read_file_content` не загружен) — **остановиться и попросить**:
> Запусти `/mcp` → выбери «claude.ai Google Drive» → авторизуйся, затем повтори.

Не пытаться поднимать собственный OAuth / Google Cloud Console — это не путь
этого скила. Вся авторизация — через коннектор claude.ai.

## База знаний (куда сохранять)

Корень базы знаний задаёт пользователь (например `knowledge/`, `docs/`, `vault/`
или текущая папка). Если корень неизвестен и не очевиден из проекта — **спросить
один раз** и дальше использовать его. Внутри корня раскладка — по содержимому
(см. шаг 4).

## Типы документов по URL

| URL содержит | Тип | Что сохраняем |
|--------------|-----|----------------|
| `/document/d/` | Google Doc | чистый Markdown |
| `/spreadsheets/d/` | Google Sheet | Markdown-таблицы (все вкладки, каждая — раздел) |
| `/presentation/d/` | Google Slides | текст по слайдам как Markdown |

## Шаги

1. **Определить тип** по шаблону URL (см. таблицу). Извлечь `file_id`
   (`/d/([a-zA-Z0-9_-]+)`).
2. **Получить содержимое** через инструменты коннектора claude.ai Google Drive:
   - `read_file_content` (fileId) — текстовое представление (Docs/Sheets/Slides).
     Основной путь.
   - `get_file_metadata` (fileId) — точное название и тип файла для frontmatter
     и имени файла.
3. **Привести к Markdown — сохраняя ВЕСЬ контент дословно** (Правило 1).
   Чистка только косметическая, контент не теряем:
   - Docs: снять экранирование (`\!`→`!`, `\.`→`.`, `\*`→`*`), тройные переносы
     → двойные, убрать пустые заголовки `#` и хвостовые пробелы. **Врезки/цитаты
     (часто приходят как `|  |`-таблицы) — оставлять, не выкидывать;** оформлять
     как блок-цитату с подписью.
   - Sheets: собрать нормальную GFM-таблицу (`| ... |`), экранировать `|` внутри
     ячеек. Одноколоночные «таблицы-обёртки» из экспорта разворачивать в список
     или осмысленную таблицу. Все строки/ячейки сохранять.
   - Slides: текст ВСЕХ слайдов, разделители между слайдами как `---` или
     `## Слайд N`. Не сокращать.
   - Сверка: финальный объём не должен быть заметно меньше исходного. Если
     что-то «не влезло» — это ошибка, а не фича.
4. **Куда сохранять — определять по содержимому самому, не спрашивать без нужды:**
   1. Понять, о чём документ (тема, проект, серия).
   2. Поискать подходящее место в базе: `grep -ril "<ключевые слова>" <корень-БЗ>`
      + посмотреть существующие папки. Если документ — часть существующей серии
      или темы (например письмо/урок №N, когда №0…№(N-1) уже лежат в какой-то
      папке) → класть туда, продолжая нумерацию/нейминг.
   3. Иначе — в подходящую тематическую папку базы; если такой нет, создать
      понятную.
   4. **Повторять frontmatter и стиль соседних файлов** (прочитать соседний
      файл), а не навязывать generic-шаблон — чтобы файл «читался как соседние».
   5. Спрашивать только если после поиска место реально неоднозначно.
5. **Проверить дубликат ПЕРЕД записью** (Правило 2). Посмотреть, нет ли уже
   такого документа в целевой папке (по названию / номеру серии). Если файл уже
   существует — **остановиться и спросить** одним вопросом:
   - **Сохранить поверх** — обновить существующий файл новой версией, или
   - **Сделать копию** — например `<имя> (v2).md` или с датой в имени.

   Молча не перезаписывать. По возможности кратко показать, чем версии
   отличаются (например: в существующем файле нет таких-то блоков/цитат).
6. **Frontmatter** — в стиле целевой папки (шаг 4.4). Если своей схемы у папки
   нет, базовый шаблон:
   ```
   ---
   source: <google-docs-url>
   type: gdoc | gsheet | gslides
   saved: <YYYY-MM-DD>
   title: <название документа>
   ---
   ```
7. **Показать полный путь** к сохранённому файлу.
8. Если документов несколько — обработать по очереди, в конце дать список путей.

## Картинки и схемы (коннектор отдаёт только текст)

Коннектор НЕ переносит картинки, схемы, диаграммы, встроенные объекты — только
текст. Поэтому:

1. **Заметить, что графика была.** Признаки в выгрузке: пустой слайд/раздел под
   заголовком (например слайд «Схема» без текста), фразы «см. схему / на рисунке /
   как показано ниже», подписи к картинкам без самой картинки.
2. **Оставить явную метку** в нужном месте файла, а не молчаливую заглушку:
   `> ⚠️ Здесь была схема/картинка — не перенеслась коннектором.`
3. **После сохранения — попросить у пользователя скриншоты** этих картинок/схем:
   перечислить, чего именно не хватает (по разделам/слайдам).
4. **Когда скриншоты пришли** — положить их рядом с `.md` (в подпапку `assets/`),
   вставить на место меток через `![подпись](assets/имя.png)` и убрать `⚠️`-метку.

## Ограничения (говорить честно)

- Коннектор отдаёт только ТЕКСТ (см. раздел про картинки выше).
- Sheets: `read_file_content` отдаёт ВСЕ вкладки книги — сохранять их все,
  каждую отдельным разделом.
- Доступ определяется аккаунтом, которым авторизован коннектор. Нет доступа →
  сказать прямо, не выдумывать содержимое.
