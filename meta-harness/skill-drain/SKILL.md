## State

- **Canon:** `~/Documents/GitHub/claude-config/commands/*.md` - always edit via a
  fresh worktree off `origin/main`, land with `git push origin HEAD:main`. The shared main tree
  is never committed in.
- **Manifest:** [Uprava/docs/skill_drain/MANIFEST.json](https://github.com/gasyoun/Uprava/blob/main/docs/skill_drain/MANIFEST.json)
  - one row per command `{name, status: pending|improved|clean|skipped, last_run, notes}`;
    statuses commit back to Uprava main every batch (land-on-main route).
- **Reports:** `Uprava/docs/skill_drain/RUN_<DD-MM-YYYY>.md` - before/after per row, appended
  per run. A run without its report did not happen.
- **Twins:** generated by
  [`scripts/generate_playbook_twins.py`](https://github.com/gasyoun/claude-config/blob/main/scripts/generate_playbook_twins.py),
  never hand-edited; verified with **both** auditors -
  [`scripts/audit_codex_twins.py`](https://github.com/gasyoun/claude-config/blob/main/scripts/audit_codex_twins.py)
  and [`scripts/audit_grok_twins.py`](https://github.com/gasyoun/claude-config/blob/main/scripts/audit_grok_twins.py).
  The generator writes both twins, so running only the Codex auditor leaves half the output
  unverified.

**Arguments** - `--batch N` (override the default 10); `--resume` (default behaviour anyway -
pick the next pending slice alphabetically); `--name <stem>` (re-drain one command outside its
turn); `--report-only` (audit + report, apply nothing - use when landing is blocked).

## Phase 0 - Manifest bootstrap (once, idempotent)

1. `git fetch origin` on BOTH repos first (a stale main holds surprises).
2. Census: list actual `commands/*.md` stems from the worktree. Count must equal disk -
   never invent rows, never carry rows for files that no longer exist (drop them with a note).
3. If MANIFEST.json exists, reconcile against the census instead of rewriting it:
   new files append as `pending`; vanished files are removed and logged in the next RUN report.
4. Commit the manifest to Uprava main from an Uprava worktree (`land-on-main` discipline).

## Phase 1 - Pick the batch

Take the first `--batch` (default **10**) `pending` rows in alphabetical order. Skip any stem
another live session has claimed (check Uprava GTD / exec-claim markers before editing).
Zero pending = the drain is DONE: say so, do not re-audit clean rows opportunistically -
full re-walks are a fresh explicit instruction.

**Exec-claim discipline (minted 26-08-2026 after the batch-35 dual-run, where two lanes
landed the same slice because slice ownership lived as prose nobody was required to read):**

1. **READ the live claims before picking.** Slice claims live in
   [`Uprava/GTD_NEXT_ACTIONS.md`](https://github.com/gasyoun/Uprava/blob/main/GTD_NEXT_ACTIONS.md)
   inside the `/skill-drain runs 2–N` row as prose of the exact shape
   `CLAIM <date> <lane>: slice A…B taken by lane wt <worktree>; do not re-drain this range until it lands`.
   Grep that row for `taken by lane`; any candidate stem inside a LIVE claimed range is skipped,
   and your batch starts at the next unclaimed head. A claim that already says `LANDED` (sha range
   present on origin) does not block anything - its range is simply landed history.
2. **STAMP your own claim before the first command edit.** Append one line in that same shape
   naming your slice + lane worktree into the runs row, commit to Uprava main from your Uprava
   worktree, and push (chained fetch-rebase-push) BEFORE touching any canonical command. An
   unstamped claim protects nobody: every lane only reads this row, so nothing else counts.
3. **Retire the claim at landing.** In Phase 3 step 6's same pass, replace your `CLAIM …` line
   with `LANDED <claude-config sha-range>` for the slice. Never delete another lane's live line;
   stale lines are reconciled by the next weekly sweep, not by you mid-run.

## Phase 2 - Per-command audit: the 8 axes

The canonical rubric is
[`references/skill-review-defect-classes.md`](https://github.com/gasyoun/claude-config/blob/main/references/skill-review-defect-classes.md)
(A1–A8, light-vs-depth split, fix rails). Read the full body of each command in the batch. For each axis record findings, then FIX:

| # | Axis | Fix shape |
|---|---|---|
| A1 | **md-hygiene contract** - dated header with REAL git creation dates (`git log --follow --diff-filter=A`), `_Last updated:` bumped only on real edits, closing byline | mechanical edit |
| A2 | **dead references** - every path/repo/tool/sibling-skill link resolves (local clones for blob URLs; `Test-Path` on Windows / `test -e` on macOS-Linux for local paths) | repoint or drop with note |
| A3 | **tier attribution** - bare `Sonnet`/`Opus`/etc. anywhere → tier + exact version form (`Sonnet 5 (claude-sonnet-5)`), provenance lines included | mechanical edit |
| A4 | **handoff-mention form** - every `H###` named as ID + short human tier + **effort light** + full title | expand stubs |
| A5 | **description triggers** - frontmatter description covers what actually invokes it; ADD missing trigger phrases, never remove existing ones | additive edit |
| A6 | **content-vs-reality drift** - workflows referencing moved tools, renamed skills, dead goals (G##), superseded docs | update to current reality |
| A7 | **table integrity** - unterminated rows, escape-eaten pipes, wrapped bullets read as rows | fix data AND generator if one emitted it |
| A8 | **phase coherence** - numbered phases reference existing sections; fence blocks closed; argument docs match the H1 signature | mechanical edit |

**A4 has a scope and a soft half.** Scope: A4 fires only where a command tells a session to *name* a handoff to a human ([`rules/handoff-mention-form.md`](https://github.com/gasyoun/claude-config/blob/main/rules/handoff-mention-form.md) scopes it to replies) - an inline historical `(H####)` inside a command body is a provenance citation, not a mention, and does not fire. Soft half: the four-part form includes the **effort light** (🟢1 trivial / 🟡2 medium / 🔴3 hard, read off the registry row, never guessed), and that rule says in its own text that no hook enforces the light - [`stop_handoff_mention_form.py`](https://github.com/gasyoun/claude-config/blob/main/hooks/stop_handoff_mention_form.py) checks tier + title only. So the light is exactly the part that rots unread, and the part this axis is worth running for.

Judgment calls (rewriting intent, re-scoping a phase, changing a recommendation) ARE applied -
the ruling is всё авто - but each such row is flagged `judgment-applied` in the RUN report so
retro-veto is possible. Everything else is `mechanical`.

## Hard rails (violation = failed run)

- NEVER rename or delete a command; retirement belongs to
  [`/playbook-canonical-source`](https://github.com/gasyoun/claude-config/blob/main/commands/playbook-canonical-source.md)'s
  census lane, never to this runner.
- NEVER touch frontmatter `name:`.
- NEVER remove an existing trigger phrase from `description`.
- NEVER hand-edit a generated twin - regenerate.
- One command = one commit on the h-batch branch, message `skill-drain(<name>): <axis list>`,
  so any single improvement is revertable alone.

## Phase 3 - Land the batch

1. Worktree off `origin/main`, per-command commits per the rails above.
2. Regenerate twins for EVERY changed command; run **both** twin auditors
   (`audit_codex_twins.py` and `audit_grok_twins.py`).
3. Gates that exist and apply: `scripts/run_hook_tests.py --changed`, both twin auditors, and
   if a card/row was touched downstream, the two census scripts - **both live in
   [`Uprava/tools/`](https://github.com/gasyoun/Uprava/tree/main/tools)**, and **neither takes
   a `--check` flag**; a bare run IS the check (`--emit` is the write mode that rewrites the
   claimed counts):

   ```sh
   python ~/Documents/GitHub/Uprava/tools/skills_manual_check.py
   python ~/Documents/GitHub/Uprava/tools/skills_index_check.py
   ```

   `skills_index_check.py` is the one that gets misfiled as a spine script: what github-spine
   owns is the [`SKILLS_INDEX.md`](https://github.com/gasyoun/github-spine/blob/main/SKILLS_INDEX.md)
   the script audits, not the script. An on-disk skill with no row in that index is a FAIL
   there, where the RU manual checker only WARNs.
4. CHANGELOG entry (one clause per batch, not per command) written as **one file under
   `changelog_queue/`** -
   claude-config became an H3355 queue repo on 02-09-2026, so a direct bullet under
   `## [Unreleased]` is the wrong shape here ([`/cut-release`](https://github.com/gasyoun/claude-config/blob/main/commands/cut-release.md)
   § queue repos). `--apply` flushes the fragments under `[Unreleased]`, promotes them and
   stages the consumed files' deletions. Then `/cut-release` mechanics when a version cut is
   owed.
5. `git push origin HEAD:main` (chained retry on rejection). Merge-leftover worktree cleanup.
6. Manifest statuses + RUN report committed to Uprava main the same pass.
7. Residuals (blocked rows, deferred axes, follow-ups) become GTD `@DO` rows immediately,
   never asked.
