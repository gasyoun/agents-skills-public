# plates-intake-qc

Use this skill when the user asks to run the migrated source command `plates-intake-qc`.

## Command Template


# /plates-intake-qc <пара|файл|glob> [--dry]

_Created: 04-10-2026 · Last updated: 04-10-2026_

Приёмка креативов из чата «Пункт приема плашек» по ТЗ [CREATIVE_PLATES_TZ_2026-09](https://github.com/gasyoun/Uprava/blob/main/docs/CREATIVE_PLATES_TZ_2026-09.md). Команда — ТОЛЬКО контроль качества: публикация с плашкой остаётся за конвейером [daily_publication_conveyor.py](https://github.com/gasyoun/Uprava/blob/main/tools/daily_publication_conveyor.py), который читает только ✅-строки реестра.

## Входы

- **Пара:** `NN` — горизонтальный пост, `st NN` — вертикальная сторис (напр. «Грамматика санскрита 01» + «Грамматика санскрита st 01»). Instagram-вариант — третья роль по таблице имён [GRAMMAR_GASUNS_UTM_STANDARD_12-09-2026](https://github.com/gasyoun/Uprava/blob/main/docs/GRAMMAR_GASUNS_UTM_STANDARD_12-09-2026.md).
- **Источник (приоритет):** MTProto-скачивание из чата по пути скилла `~/.agents/skills/anons/SKILL.md` (§ Server-side Telegram story operations, шаги 1–2): резолв диалога «Пункт приема плашек» в Telegram peer id через включённую аккаунт-сессию (display-имя MTProto не принимается), затем `telegram:fetch-story-media` с точным message ID; «последнее сообщение с медиа» — только когда инструкция говорит это явно.
- **Фолбэк:** локальные мастера (напр. `~/Downloads`), если файлы уже скачаны — provenance (кто/когда/откуда) фиксируется в QC-отчёте.

## Чеки (все обязательны, порядок фиксируется в отчёте)

1. **Размеры:** пост = ровно 1920×1080; `st` = ровно 1080×1920 — `sips -g pixelWidth -g pixelHeight <файл>`. Instagram-вариант: горизонтальная роль 1920×1080, отдельный вертикальный файл 1080×1920.
2. **Парность:** горизонтальный и `st`-файл одной пары несут ОДИНАКОВЫЕ день/дату/время (сравнить OCR-строки, подтвердить глазами). Расхождение = FAIL пары с именем обоих файлов. Реальный прецедент G26-C: чат-группы «01 + st 01»/«02 + st 02» перемешаны (01 = вторник 22.09, st 01 = суббота 19.09) — правильные пары 01+st 02 и 02+st 01.
3. **OCR-фильтр запрещённых слов:**

```bash
printf '%s\n' <пути-файлов> | swift ~/Documents/GitHub/Uprava/tools/ocr_plate.swift
```

   grep по шести словам: «школа», «академия», «успейте», «последний шанс», «скидка», «только сегодня». OCR — ТОЛЬКО фильтр, глазам замены нет.
4. **Проверка глазом:** каждый файл открыть как изображение: URL, даты, название, логотип читаемы и совпадают с OCR. Макет не оценивается и не меняется.
5. **Сверка со строкой реестра:** точное название курса = колонка `ru_text`, деванагари = колонка `devanagari`, адрес = колонка `url` строки [content/creative_plates_status.tsv](https://github.com/gasyoun/Uprava/blob/main/content/creative_plates_status.tsv). URL на плашке обязан быть `samskrte.ru/...`; `samskrtam.ru` = FAIL (старый домен). Строки реестра под курс плашки нет = FAIL «нет строки реестра» — реестр расширяет MG, команде флипать нечего.
6. **Статус:** все пять чеков зелёные → флип.

## Флип (только после всех зелёных; при `--dry` — пропустить)

Append-only overlay: в [creative_plates_status.tsv](https://github.com/gasyoun/Uprava/blob/main/content/creative_plates_status.tsv) ДОБАВИТЬ новую строку с тем же `id` (содержательные колонки повторить), `status` = `✅`, в `notes` — дата QC и имена прошедших файлов. Исходную строку НЕ переписывать: конвейер берёт первую готовую (✅) строку по course_id (`load_plates` → `plate_for_course`), поэтому overlay-строка выигрывает корректно. Затем записать вердикт в чат «Пункт приема плашек» тем же MTProto-путем (сообщение о результате приёмки — не публикация плашки; инструмента отправки нет — отдать текст вердикта человеку для вставки).

## Никогда

- не публиковать ничего наружу — публикация с плашкой = конвейер post-factum ✅-статуса;
- не менять макет, пиксели или размеры плашки;
- не пропускать файл без проверки глазом;
- не флипать строку при любом красном чеке;
- при `--dry` не делать ни одной записи — ни TSV, ни чат.

## Машинный гейт

`exit 0` — все чеки зелёные и (при отсутствии `--dry`) флип+запись выполнены; `exit 1` — первый красный чек с именем файла и причиной. `--dry` + `exit 0` = «QC пройден, записи сухие».
